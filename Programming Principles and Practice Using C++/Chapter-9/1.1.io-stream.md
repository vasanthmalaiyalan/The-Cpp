§9.2-ல் Stroustrup உண்மையில் `cin`, `cout` எப்படி வேலை செய்கின்றன என்பதற்கான **mental model**-ஐ கொடுக்கிறார்.

---

# Big Picture

நாம் இதுவரை:

```cpp
std::cin >> age;
std::cout << age;
```

என்று பயன்படுத்தினோம்.

ஆனால் உண்மையில் என்ன நடக்கிறது?

```text
Keyboard
   ↓
 Buffer
   ↓
istream (cin)
   ↓
Program
   ↓
ostream (cout)
   ↓
Buffer
   ↓
Screen
```

---

# ostream என்றால் என்ன?

`ostream` = Output Stream

இதன் வேலை:

```cpp
std::cout << 25;
```

இங்கே:

```text
Integer 25
    ↓
"25"
    ↓
Characters
    ↓
Screen
```

---

## ostream converts values into characters

```cpp
int age {24};

std::cout << age;
```

Computer memory-ல்:

```text
00011000
```

இருக்கும்.

ஆனால் மனிதனுக்கு:

```text
24
```

காட்ட வேண்டும்.

அதனால் ostream:

```text
int
 ↓
characters
 ↓
"24"
```

ஆக மாற்றுகிறது.

---

# ostream doesn't know destination

```cpp
std::cout << "Hello";
```

Program-க்கு:

```text
Monitor?
File?
Network?
```

என்று தெரியாது.

அது ostream-க்கு எழுதுகிறது.

---

உதாரணம்:

```cpp
std::ofstream file {"log.txt"};

file << "Hello";
```

அதே operator.

Destination மட்டும் மாறியுள்ளது.

```text
cout  -> Screen

file  -> File
```

# Buffer என்றால் என்ன?

Book-ல் முக்கியமாக buffer பற்றி பேசுகிறார்.

Suppose:

```cpp
std::cout << "A";
```

நீ உடனே screen-ல் வரும் என்று நினைக்கிறாய்.

ஆனால் பல நேரங்களில்:

```text
Program
  ↓
Buffer
```

முதலில் போகும்.

---

Buffer என்பது:

```text
Temporary memory
```

---

Example:

```cpp
std::cout << "A";
std::cout << "B";
std::cout << "C";
```

OS-க்கு 3 separate writes அனுப்புவதற்கு பதில்:

```text
ABC
```

ஒரே தடவையில் அனுப்பும்.

இதனால் performance அதிகரிக்கும்.

---

# Best Professional Example

இந்த program-ல்:

* Keyboard
* File
* String

மூன்றிலிருந்தும் ஒரே code style-ல் data படிக்கிறோம்.

```cpp
#include <fstream>
#include <iostream>
#include <sstream>
#include <string>

int main()
{
    int keyboard_age {};
    int file_age {};
    int string_age {};

    // Keyboard stream
    std::cout << "Enter age: ";
    std::cin >> keyboard_age;

    // File stream
    std::ifstream input_file {"age.txt"};

    if (input_file)
    {
        input_file >> file_age;
    }

    // String stream
    std::istringstream input_string {"99"};

    input_string >> string_age;

    std::cout << "\nResults\n";
    std::cout << "Keyboard age : "
              << keyboard_age << '\n';

    std::cout << "File age     : "
              << file_age << '\n';

    std::cout << "String age   : "
              << string_age << '\n';
}
```

# The Most Important Idea in §9.2

Stroustrup wants you to understand:

```text
istream
    ↓
read values

ostream
    ↓
write values
```

and

```text
Keyboard
File
Network
Memory String
```

இவை எல்லாம் details.

Programmer-ஆக நீ:

```cpp
stream >> value;
stream << value;
```

என்று மட்டுமே சிந்திக்க வேண்டும்.

இதுதான் **I/O Stream Model**-ன் முழு நோக்கம். Once this idea clicks, `cin`, `cout`, `ifstream`, `ofstream`, `stringstream`, network streams எல்லாம் ஒரே family என்று புரிய ஆரம்பிக்கும்.

------------------------------


இரண்டும் valid தான்! ஆனால் வித்தியாசம் இருக்கிறது.

---

## `int age` — Initialize இல்லாமல்

```cpp
struct Person
{
    std::string name;
    int age;    // garbage value இருக்கும்!
};

Person p;
std::cout << p.age;  // ❌ unpredictable — 0 வரலாம், 
                     //    -858993460 வரலாம், எதுவும் வரலாம்!
```

---

## `int age {}` — Zero Initialize

```cpp
struct Person
{
    std::string name;
    int age {};  // guaranteed 0!
};

Person p;
std::cout << p.age;  // ✅ எப்போதும் 0
```

---

## ஏன் `{}` பயன்படுத்துகிறோம்?

```cpp
Person loaded_person {};  // main உள்ளே இப்படி create செய்தீர்கள்
```

File படிக்கும் முன்பு `load_person` fail ஆனால்:

```cpp
// int age; ஆக இருந்தால்
loaded_person.age = garbage value  ❌

// int age {}; ஆக இருந்தால்  
loaded_person.age = 0              ✅ predictable!
```

---

**சுருக்கம்:** `int age` technically சரிதான் — ஆனால் `int age {}` கொடுப்பது **safe**, **predictable**, மேலும் இது ஒரு **good practice!**
