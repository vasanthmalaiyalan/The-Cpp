## `file.exceptions()` என்றால் என்ன?

இது file stream-ல் எந்த நிலைமைகளில் **exception throw** செய்யணும்னு சொல்வது.

---

### இல்லாம போனா என்ன ஆகும்?

பொதுவா `ifstream` error வந்தாலும் **silent-ஆ fail ஆகும்** — exception எதுவும் வராது. நீங்க manually check பண்ணணும்:

```cpp
if (!file) { /* handle error */ }
```

---

### இருந்தா என்ன ஆகும்?

```cpp
file.exceptions(std::ios::badbit | std::ios::failbit);
```

இந்த இரண்டு bit-களை set பண்றோம்:

| Bit | எப்போ trigger ஆகும் |
|---|---|
| `badbit` | file corrupt, hardware error மாதிரி serious problem |
| `failbit` | file open ஆகல, format mismatch போன்றவை |

இவை ஏதாவது நடந்தா **`std::ios::failure` exception** automatically throw ஆகும்.

---

### இந்த code-ல் எப்படி வேலை செய்யது?

```cpp
std::ifstream file {file_name};
file.exceptions(...);  // ← இங்க set பண்றோம்
```

`numbers.txt` இல்லன்னா → `failbit` set ஆகும் → exception throw → `main()`-ல் `catch` பிடிக்கும் → `ex.what()` print ஆகும்.

---

### ஒரு subtle point

`while (file >> value)` — loop EOF-ல நிக்கும். ஆனா `failbit` set பண்ணிருக்கோம், EOF-ல `eofbit` மட்டும் set ஆகும் (failbit இல்ல), so **loop சரியா முடியும்**, exception வராது. இது intentional design.

சுருக்கமா: manual error check இல்லாம, exception-based error handling-க்கு இது உதவுது.

## `ios` என்றால் என்ன?

**`ios`** என்பது **Input/Output Stream** என்பதன் சுருக்கம்.

---

### Full form:

```cpp
std::ios        // Input Output Stream
std::ios_base   // இதுதான் base class
```

---

### Class hierarchy:

```
std::ios_base
      ↓
   std::ios
      ↓
std::istream    std::ostream
      ↓               ↓
  std::ifstream   std::ofstream
```

- `ifstream` → **i**nput **f**ile stream
- `ofstream` → **o**utput **f**ile stream
- `ios` → இவை இரண்டுக்கும் **பொதுவான** base class

---

### `std::ios::badbit` என்பது:

`ios` class-க்குள் define பண்ணப்பட்ட **static constant** — அதான் `::` use பண்றோம்:

```cpp
std::ios::badbit   // ios class-ல உள்ள badbit constant
std::ios::failbit  // ios class-ல உள்ள failbit constant
std::ios::eofbit   // ios class-ல உள்ள eofbit constant
```

சுருக்கமா: `ios` என்பது C++ stream system-ன் **அடிப்படை class**, அதுல உள்ள constants-தான் நாம் use பண்றோம்.

-----------------------------


It is completely understandable to be frustrated by this! You fixed the typo and you removed `failbit` from the exception mask, so logically, it feels like it shouldn't be throwing that exception anymore.

However, you've hit another sneaky quirk of how C++ stream exceptions work.

---

### The Culprit: Setting exceptions *after* the file is open

Look at the exact order of operations in your function:

```cpp
file.open(file_name); // 1. Opens file. EOF is NOT reached yet.

if (!file.is_open()) { ... }

file.exceptions(std::ios::badbit); // 2. You set the mask to JUST badbit.

while (file >> value) { ... } // 3. Reads all numbers. Hits EOF.

```

When your `while` loop finishes reading `12`, it tries to read one more time. It hits the end of the file. This causes C++ to set **both** the `eofbit` (End of File) and the `failbit` (because the read failed).

Since your mask only has `badbit`, the loop exits perfectly cleanly. **No exception is thrown here.**

The crash happens right after the loop finishes. When the `read_numbers` function ends, the `std::ifstream file` object goes out of scope, so its **destructor** is called automatically to close the file.

Inside the C++ standard library destructor for `std::ifstream`, it tries to safely shut down and clear the stream flags using an internal call to `.clear()`. Because `failbit` was set during the loop, calling `.clear()` while an active exception mask exists triggers a bug/quirk in some older compiler standard libraries (like certain versions of GCC/libstdc++), causing it to throw `basic_ios::clear: iostream error` on destruction!

---

### The Cleanest Fix

If you want to use `file.exceptions()`, the golden rule in C++ is to **set the exception mask BEFORE you open the file**, or simply avoid setting it at all if you are manually handling errors.

Here is the code fixed by moving the mask to the very top of the function:

```cpp
#include <iostream>
#include <fstream>
#include <vector>

std::vector<int> read_numbers(const std::string& file_name) {
    std::ifstream file;

    // 1. Set the exception mask FIRST (only badbit)
    file.exceptions(std::ios::badbit);

    // 2. Open the file
    file.open(file_name);

    // 3. Check if it opened successfully
    if (!file.is_open()) {
        throw std::runtime_error("Could not open file: " + file_name);
    }

    std::vector<int> values {};
    int value {};

    while (file >> value) {
        values.push_back(value);
    }

    return values; // File destructs cleanly now!
}

int main() {
    std::ofstream create_file("numbers.txt");
    create_file << "123 2345 456 12";
    create_file.close();

    try {
        const auto values = read_numbers("numbers.txt");
        for (int value : values) {
            std::cout << value << '\n';
        }
    }
    catch (const std::exception& ex) {
        std::cerr << "Error: " << ex.what() << '\n';
    }
}

```

### Alternatively: Drop `file.exceptions()` completely

In modern C++, most developers avoid `file.exceptions()` entirely because of these strange edge cases. Checking streams manually is much more predictable:

```cpp
std::vector<int> read_numbers(const std::string& file_name) {
    std::ifstream file(file_name); // Opens automatically

    if (!file) { // Checks if open failed OR if badbit is set
        throw std::runtime_error("Could not open or read file: " + file_name);
    }

    std::vector<int> values {};
    int value {};

    while (file >> value) {
        values.push_back(value);
    }

    return values;
}

```
