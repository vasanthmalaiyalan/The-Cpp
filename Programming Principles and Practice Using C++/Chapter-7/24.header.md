# Why Needed?

Suppose:

```text id="5uwma1"
main.cpp
```

includes:

```text id="9uwma2"
f.h
```

AND another header also includes `f.h`.

Then compiler same declarations-ஐ
multiple times பார்க்கும்.

---

# Example Problem

Without include guard:

```cpp id="3uwma3"
class Token
{
};
```

included twice.

Compiler sees:

```cpp id="7uwma4"
class Token {};
class Token {};
```

---

# Error

```text id="1uwma5"
redefinition of class Token
```

---

# Include Guard Solves This

---

# Step-by-step

## 1.

```cpp id="4uwma6"
#ifndef F_H
```

Means:

```text id="8uwma7"
"If F_H is NOT defined"
```

---

# 2.

```cpp id="2uwma8"
#define F_H
```

Means:

```text id="6uwma9"
"Now define F_H"
```

---

# 3.

Compiler processes header contents.

---

# 4.

```cpp id="0uwmb0"
#endif
```

Ends condition.

---

# First Include

Suppose first time:

```cpp id="5uwmb1"
#include "f.h"
```

---

# Preprocessor checks

```cpp id="9uwmb2"
#ifndef F_H
```

Is `F_H` defined?

NO.

So continue.

---

# Then

```cpp id="3uwmb3"
#define F_H
```

Now:

```text id="7uwmb4"
F_H exists
```

---

# Header contents included.

---

# Second Include

Again:

```cpp id="1uwmb5"
#include "f.h"
```

---

# Now:

```cpp id="4uwmb6"
#ifndef F_H
```

fails.

Because:

```text id="8uwmb7"
F_H already defined
```

---

# So compiler skips entire header.

Problem solved.

| Directive     | Meaning                     |

# Real-world Importance

Without include guards:

This tiny pattern became one of the most important patterns in C/C++ history.
