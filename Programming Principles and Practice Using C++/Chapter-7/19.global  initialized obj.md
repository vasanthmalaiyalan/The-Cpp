## Part 1: `Date get_date_from_clock()`

```cpp
Date get_date_from_clock()
{
    return {"2026-05-19"};
}
```

```
Date        → return type (Date struct return பண்ணும்)
get_date_from_clock → function பெயர்
()          → parameters இல்லை

return {"2026-05-19"} → Date struct-ஐ
                        value = "2026-05-19" ஆக
                        create பண்ணி return பண்ணும்
```

இது simple — **Date object ஒன்று create பண்ணி return பண்ணும்.**

## உள்ளே என்ன நடக்கும்:

```cpp
const Date& today()
{
    static const Date today =    // static keyword!
        get_date_from_clock();

    return today;
}
```

### `static` என்றால் என்ன இங்கே:

```
Normal local variable:
┌─────────────────────────────┐
│ function call ஆகும்போது     │
│ → create ஆகும்              │
│ function முடியும்போது       │
│ → destroy ஆகும்             │
└─────────────────────────────┘

static local variable:
┌─────────────────────────────┐
│ FIRST call மட்டும்          │
│ → create ஆகும்              │
│ Program முடியும் வரை        │
│ → alive இருக்கும்!          │
│ Second call-ல்              │
│ → already exists, skip!     │
└─────────────────────────────┘
```

---

## Visually என்ன நடக்கும்:

```cpp
const Date& d1 = today();  // FIRST call
const Date& d2 = today();  // SECOND call
```

```
First call:
today() →  static today exist? NO
           → get_date_from_clock() call பண்ணும்
           → "Getting current date" print ஆகும்
           → static today create ஆகும்
           → reference return பண்ணும்

Second call:
today() →  static today exist? YES
           → get_date_from_clock() call பண்ணாது!
           → same static object return பண்ணும்
```

```
Output:
Getting current date   ← ஒரு முறை மட்டும்!
Today : 2026-05-19
Today again : 2026-05-19
```

## ஏன் `const Date&` return பண்றோம்? Copy பண்ணாமல்:

```cpp
// Date return பண்ணினால்:

```

## `const` ஏன் இரண்டு இடத்திலும்:

```cpp
const Date& today()        // return = const reference
{
    static const Date today = // object = const, மாற்ற முடியாது
        get_date_from_clock();
    return today;
}
```

```
static const Date today → object-ஐ மாற்ற முடியாது
const Date& return      → caller-உம் மாற்ற முடியாது

// Main-ல்:
const Date& d1 = today();
d1.value = "2099";  // ❌ ERROR! const reference
```

## Full Flow:

```
main()
  │
  ├── today() — first call
  │     │
  │     ├── static exist? NO
  │     ├── get_date_from_clock() → Date{"2026-05-19"}
  │     ├── static today = Date{"2026-05-19"} (created once)
  │     └── return reference to static today
  │
  ├── today() — second call
  │     │
  │     ├── static exist? YES
  │     └── return same reference (no creation!)
  │
  └── d1 == d2 == same object ✅
```

|---|---|
| `static` local | ஒரு முறை மட்டும் create — program முடியும் வரை alive |
| `const Date` | object மாற்ற முடியாது |
| `const Date&` | copy இல்லை, reference மட்டும் return |
| `get_date_from_clock()` | Date object create பண்ணி return |

> **One line:** `static` = ஒரு முறை மட்டும் initialize, `const Date&` = copy இல்லாமல் reference return — இதனால் `today()` எத்தனை முறை call பண்ணினாலும் clock ஒரு முறை மட்டும் படிக்கும்.

இந்த section மிகவும் famous C++ problem பற்றி:

# Global Initialization Problem

இது real-world C++ systems-ல் dangerous bug source.

---

# Core Idea

Global variables:
program start ஆகும் முன்பே initialize ஆகும்.

---

# Example

```cpp id="0owmx0"
int x1 = 1;

int y1 = x1 + 2;
```

---

# Initialization Order

Same file-ல்:

top-to-bottom.

---

# So:

```text id="7owmx1"
x1 = 1
y1 = 3
```

Safe.

---

# Problem Starts

When globals exist in:
different `.cpp` files.

---

# File 1

```cpp id="3owmx2"
int x1 = 1;

int y1 = x1 + 2;
```

---

# File 2

```cpp id="9owmx3"
extern int y1;

int y2 = y1 + 2;
```

---

# Dangerous Question

Which file initializes first?

---

# Answer

## C++ does NOT guarantee.

---

# Possible Scenario 1

f1.cpp initialized first.

---

# Then

```text id="4owmx4"
x1 = 1
y1 = 3
y2 = 5
```

Looks correct.

---

# Possible Scenario 2

f2.cpp initialized first.

---

# Then:

At that moment:

```text id="2owmx5"
y1 still not initialized
```

---

# Global memory initially zeroed.

So:

```text id="6owmx6"
y1 = 0
```

temporarily.

---

# Then

```text id="8owmx7"
y2 = 0 + 2
```

So:

```text id="1owmx8"
y2 = 2
```

---

# Later

f1.cpp initializes:

```text id="5owmx9"
x1 = 1
y1 = 3
```

BUT:
y2 already became 2.

---

# Final Result

Unexpected:

```text id="3owmy0"
y2 = 2
```

instead of:

```text id="9owmy1"
5
```

---

# This Problem Called

# Static Initialization Order Fiasco

Very famous C++ issue.

---

# Author Strongly Warns

Avoid:

* globals
* complicated global initialization
* cross-file global dependencies

---

# Why globals dangerous?

Programmer cannot easily know:

* who changes them
* initialization order
* hidden dependencies

---

# Especially Bad

```cpp id="7owmy2"
short global names
```

like:

```text id="4owmy3"
x
y
z
```

Huge readability problem.

---

# Dangerous Example

```cpp id="0owmy4"
const Date today = get_date_from_clock();
```

---

# Why suspicious?

Because:

```text id="8owmy5"
When exactly is today initialized?
```

Maybe:
some other global uses it earlier.

---

# Author says

We basically cannot guarantee safety.

---

# Better Technique

Use function.

---

# Example

```cpp id="2owmy6"
const Date today()
{
    return get_date_from_clock();
}
```

---

# Benefit

Initialization happens:
when function called.

NOT during mysterious global startup phase.

---

# But Another Problem

This creates new Date every call.

Potentially expensive.

---

# Best Solution

Static local variable.

---

# Example

```cpp id="6owmy7"
const Date& today()
{
    static const Date today =
        get_date_from_clock();

    return today;
}
```

---

# Extremely Important Modern C++ Pattern

This is VERY widely used.

---

# What happens?

---

# First Call

```text id="1owmy8"
today variable created
```

and initialized.

---

# Later Calls

Same object reused.

No repeated construction.

---

# Important Benefit

C++ guarantees:
local static initialized safely.

---

# Lifetime

This static object:
lives entire program duration.

---

# BEST BOOK-ORIENTED .CPP EXAMPLE

```cpp id="0owmz3"
#include <iostream>
#include <string>


// ======================================
// Dangerous global initialization
// ======================================

int x1 = 1;

int y1 = x1 + 2;


// ======================================
// Simulated Date class
// ======================================

struct Date
{
    std::string value;
};


// ======================================
// Simulated clock function
// ======================================

Date get_date_from_clock()
{
    std::cout
        << "Getting current date\n";

    return {"2026-05-19"};
}


// ======================================
// Safe function-local static
// ======================================

const Date& today()
{
    static const Date today =
        get_date_from_clock();

    return today;
}


// ======================================
// Main
// ======================================

int main()
{
    std::cout
        << "x1 = "
        << x1
        << '\n';


    std::cout
        << "y1 = "
        << y1
        << '\n';


    const Date& d1 = today();

    const Date& d2 = today();


    std::cout
        << "Today : "
        << d1.value
        << '\n';


    std::cout
        << "Today again : "
        << d2.value
        << '\n';
}
```

# What this code teaches

| Concept                         | Example                   |
| ------------------------------- | ------------------------- |
| Global initialization           | `x1`, `y1`                |
| Global dependency danger        | `y1 = x1 + 2`             |
| Runtime initialization function | `get_date_from_clock()`   |
| Function-local static           | `static const Date today` |
| Construct once only             | first function call       |
| Reuse object                    | later calls               |
| Return by const reference       | avoid copy                |

Modern professional C++ code strongly avoids:
