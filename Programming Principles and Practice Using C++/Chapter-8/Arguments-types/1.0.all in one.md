இந்த **§8.7.1 Argument types**-ல் Stroustrup சொல்லும் core idea:

> **"Correct types பயன்படுத்தினால் compiler பல bugs-ஐ compile time-லேயே பிடித்துவிடும்."**

இது modern C++ design-ன் மிகவும் முக்கியமான principle.

# Problem with Old Date Design

முதலில்:

```cpp id="8ph7qb"
class Date
{
public:
    Date(int y, int m, int d);

private:
    int y;
    int m;
    int d;
};
```

---

Usage:

```cpp id="o6g8qg"
Date d1{4,5,2005};
```

Question:

```text id="wzzijm"
year = 4 ?
month = 5 ?
day = 2005 ?
```

Oops.

---



Different countries different conventions.

# Compiler Now Protects Us

## Wrong

```cpp id="k9ep3g"

```

Compiler error.

Because:

```text id="j9v1zd"
2nd argument must be Month
```

---

This is the BIG idea.

Compiler catches mistake BEFORE running program.

```cpp id="x1o3h2"
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec

class Date
{
public:

        : y{yy},
          m{mm},
          d{dd}

    }

    {
        std::cout
            << y << '/'
            << static_cast<int>(m)
            << '/'
            << d
            << '\n';

    int y;
    Month m;
    int d;

    d.print();
}
```

```text id="ly9oqh"

```

# Why Month::mar ?

Book explains:

Use:

```cpp id="tfivq5"
Month::mar
```

NOT:

```cpp id="t6vctt"
Month.mar
```

---

Why?

Because:

```cpp id="4c8j0y"
Month
```

is a type.

NOT object.

---

`.` is for objects:

```cpp id="sn5by5"
object.member
```

---

`::` is for:

```text id="2nv5tx"
type scope
namespace scope
class scope
enum scope
```

# Complete Professional Example

```cpp id="y1zrzr"
#include <iostream>
#include <stdexcept>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

struct Year
{
    int y;
};

class Date
{
public:

    Date(Year yy, Month mm, int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
        if(dd < 1 || dd > 31)
        {
            throw std::runtime_error("invalid day");
        }
    }

    void print() const
    {
        std::cout
            << y.y
            << '/'
            << static_cast<int>(m)
            << '/'
            << d
            << '\n';
    }

private:

    Year y;
    Month m;
    int d;
};

int main()
{
    Date good
    {
        Year{1998},
        Month::mar,
        30
    };

    good.print();
}
```

Output:

```text id="uzsyh5"
1998/3/30
```

# Final Big Idea of §8.7.1

Instead of:

```cpp id="w15y94"
Date(int,int,int)
```

use:

```cpp id="80sm5x"
Date(Year,Month,int)
```

because:

```text id="6cteb2"
Good types
    ↓
better compiler checking
    ↓
fewer bugs
    ↓
safer interfaces
```

This is one of the deepest ideas in C++ design:

> **Use the type system to make invalid code impossible or difficult to write.**
