இந்த **§8.4.6 Reporting errors**-ல் Stroustrup சொல்லும் முக்கிய கருத்து:

> **"Invalid object உருவாகும் முன்பே தடுக்க வேண்டும்."**

முன்னைய section-ல்:

```cpp
Date birthday{1970,12,30};
```

valid date.

ஆனால்:

```cpp
Date bad{2025,14,50};
```

invalid date.

Question:

```text
What should Date constructor do?
```

---

# Wrong Approach

Ignore error:

```cpp
Date::Date(int yy,int mm,int dd)
    : y{yy}, m{mm}, d{dd}
{
}
```

Now:

```cpp
Date bad{2025,14,50};
```

created successfully.

---

Later:

```cpp
bad.add_day(1);
```

or

```cpp
std::cout << bad;
```

may produce nonsense.

---

# Stroustrup's Rule

Never create an invalid object.

If invalid:

```text
Throw exception immediately
```

---

# Book Design

```cpp
class Date
{
public:
    class Invalid { };

    Date(int y,int m,int d);

    bool is_valid();

private:
    int y;
    int m;
    int d;
};
```

# Nested Exception Class

Book:

```cpp
class Invalid { };
```

inside Date.

Meaning:

```cpp
Date::Invalid
```

is a special error type.

---

Usage:

```cpp
throw Invalid{};
```

---

Think:

```text
Date says:
"I found a bad date"
```

# Book-Oriented Implementation

```cpp
#include <iostream>

class Date
{
public:

    class Invalid { };

    Date(int yy,int mm,int dd);

    bool is_valid();

private:

    int y;
    int m;
    int d;
};

Date::Date(int yy,int mm,int dd)
    : y{yy},
      m{mm},
      d{dd}
{
    if(!is_valid())
    {
        throw Invalid{};
    }
}

bool Date::is_valid()
{
    return 0 < m && m < 13;
}
```

This is almost exactly the book structure.

---

# What Happens?

Valid:

```cpp
Date d{2025,12,24};
```

Constructor:

```cpp
is_valid()
```

returns:

```text
true
```

Object created.

---

Invalid:

```cpp
Date d{2025,15,24};
```

Constructor:

```cpp
is_valid()
```

returns:

```text
false
```

Then:

```cpp
throw Invalid{};
```

Object creation stops.

---

# Why Separate is_valid()?

Book asks:

Why not write everything in constructor?

---

Bad:

```cpp
Date::Date(int yy,int mm,int dd)
{
    if(mm < 1 || mm > 12)
    {
        ...
    }
}
```

---

Better:

```cpp
if(!is_valid())
{
    throw Invalid{};
}
```

because:

```text
Validation logic
    ≠
Construction logic
```

Different responsibilities.

---

Also:

Later we may have:

```cpp
Date(int y);
Date(string text);
Date(time_t t);
```

Multiple constructors.

All can reuse:

```cpp
is_valid()
```

# Full Book-Oriented Example

```cpp
#include <iostream>

class Date
{
public:

    class Invalid { };

    Date(int yy,int mm,int dd);

    void add_day(int n);

    bool is_valid();

    int year()  { return y; }
    int month() { return m; }
    int day()   { return d; }

private:

    int y;
    int m;
    int d;
};

Date::Date(int yy,int mm,int dd)
    : y{yy},
      m{mm},
      d{dd}
{
    if(!is_valid())
    {
        throw Invalid{};
    }
}

bool Date::is_valid()
{
    return
        (m >= 1 && m <= 12)
        &&
        (d >= 1 && d <= 31);
}

void Date::add_day(int n)
{
    d += n;
}

std::ostream& operator<<(std::ostream& os, Date d)
{
    return os
        << d.year()
        << '/'
        << d.month()
        << '/'
        << d.day();
}

void f(int x,int y)
try
{
    Date dxy{2024,x,y};

    std::cout << dxy << '\n';

    dxy.add_day(2);
}
catch(Date::Invalid)
{
    std::cout
        << "f(): invalid date\n";
}

int main()
{
    f(12,24);

    f(15,10);
}
```

Output:

```text
2024/12/24
f(): invalid date
```

# Understanding the try/catch

Book:

```cpp
void f(int x,int y)
try
{
    Date dxy{2024,x,y};

    ...
}
catch(Date::Invalid)
{
    error("f(): invalid date");
}
```

Meaning:

---

If:

```cpp
Date dxy{2024,12,24};
```

valid

↓

normal execution.

---

If:

```cpp
Date dxy{2024,15,24};
```

invalid

↓

constructor throws:

```cpp
Date::Invalid{}
```

↓

control jumps directly to:

```cpp
catch(Date::Invalid)
```

↓

error handled.

---

# Why This Is Powerful

Without validation:

```cpp
Date bad{2025,99,500};
```

exists.

Dangerous.

---

With validation:

```cpp
Date bad{2025,99,500};
```

never exists.

Impossible state.

# The Key OOP Idea: Invariant

Previous section introduced:

```text
Invariant
=
Rule that must always be true
```

For Date:

```text
1 <= month <= 12
1 <= day <= valid day range
```

---

Constructor checks invariant:

```cpp
if(!is_valid())
{
    throw Invalid{};
}
```

Therefore:

```text
Object created
      ↓
Guaranteed valid
      ↓
Member functions assume validity
```

---

# What Stroustrup Wants You To Learn

This section completes another step in the evolution:

```text
struct Date
      ↓
helper functions
      ↓
member functions
      ↓
constructor
      ↓
private data
      ↓
validity checking
      ↓
exceptions
```

The professional design rule is:

> **Don't allow invalid objects to exist. Check validity in the constructor and throw an exception immediately when the invariant is violated.**
