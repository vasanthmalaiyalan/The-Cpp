# Version 1 - Old Design (Dangerous)

```cpp
#include <iostream>

struct Date
{
    int y;
    int m;
    int d;
};

void init_day(Date& dd, int year, int month, int day)
{
    dd.y = year;
    dd.m = month;
    dd.d = day;
}

int main()
{
    Date today;          // uninitialized

    std::cout << today.d << '\n';   // BUG

    init_day(today, 2025, 12, 24);
}
```

---

## Memory View

After:

```cpp
Date today;
```

memory may contain:

```text
today
 ├── y = 492813
 ├── m = -22
 └── d = 9812
```

random garbage values.

---

Then:

```cpp
std::cout << today.d;
```

Output:

```text
9812
```

or

```text
-58372
```

or something else.

Nobody knows.

---

# Why Bug Happened?

Because programmer forgot:

```cpp
init_day(today, 2025, 12, 24);
```

before using object.

Imagine:

```cpp
Date invoice_date;

```

Now garbage date enters database.

# Second Problem

Programmer manually creates tomorrow.

```cpp
#include <iostream>

struct Date
{
    int y;
    int m;
    int d;
};

int main()
{
    Date today;

    today.y = 2025;
    today.m = 12;
    today.d = 31;

    Date tomorrow;

    tomorrow.y = today.y;
    tomorrow.m = today.m;
    tomorrow.d = today.d + 1;

    std::cout
        << tomorrow.d << '/'
        << tomorrow.m << '/'
        << tomorrow.y
        << '\n';
}
```

Output:

```text
32/12/2025
```

---

Looks innocent:

```cpp
tomorrow.d = today.d + 1;
```

but produces:

```text
32 December 2025
```

which is impossible.

---

# Why Did Programmer Do This?

Because Date has no operation.

Only raw data.

So programmer starts manipulating fields directly.

```cpp
today.d
today.m
today.y
```

---

# Stroustrup's Solution

Move behavior into Date itself.

---

# Better Design

```cpp
#include <iostream>

struct Date
{
    int y;
    int m;
    int d;

    Date(int year, int month, int day);

    void add_day(int n);
};
```

---

Now programmer writes:

```cpp
Date today{2025,12,31};

today.add_day(1);
```

instead of:

```cpp
today.d = today.d + 1;
```

# Manual Constructor Example

```cpp
#include <iostream>
#include <stdexcept>

struct Date
{
    int y;
    int m;
    int d;

    Date(int year, int month, int day)
    {
        if(month < 1 || month > 12)
        {
            throw std::runtime_error("invalid month");
        }

        if(day < 1 || day > 31)
        {
            throw std::runtime_error("invalid day");
        }

        y = year;
        m = month;
        d = day;
    }

    void add_day(int n)
    {
        d += n;
    }
};

int main()
{
    Date today{2025,12,31};

    today.add_day(1);

    std::cout
        << today.d << '/'
        << today.m << '/'
        << today.y
        << '\n';
}
```

# Biggest Improvement

Old design:

```cpp
Date today;
```

Allowed.

Dangerous.

---

New design:

```cpp
Date today;
```

Compiler error.

Because constructor requires:

```cpp
year
month
day
```

---

Must write:

```cpp
Date today{2025,12,31};
```

Now forgetting initialization becomes impossible.

---

# What Stroustrup Wants You To Learn

Bad design:

```cpp
struct Date
{
    int y;
    int m;
    int d;
};
```

Programmer can:

```cpp
today.d = 999;
today.m = 50;
```

or forget initialization.

---

Better design:

```cpp
struct Date
{
    Date(int,int,int);
    void add_day(int);
};
```

Now Date itself controls:

* initialization
* validation
* date operations

This is the beginning of **encapsulation** and **class-oriented design** in C++.
