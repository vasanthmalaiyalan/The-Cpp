இந்த **§8.7.4 const member functions**-ல் Stroustrup சொல்லும் மிக முக்கியமான idea:

> **"ஒரு function object-ஐ மாற்றுமா இல்லையா என்பதை type system-லேயே தெளிவாக சொல்ல வேண்டும்."**

இது professional C++ design-இல் மிகவும் முக்கியமான concept.



---

# First Problem

Suppose:

```cpp id="o8y8iu"
Date d;

const Date start_of_term;
```

---

இங்கே:

```cpp id="sijjlwm"
d
```

↓

modifiable object

---

```cpp id="jlwm5f"
start_of_term
```

↓

constant object

Change செய்யக்கூடாது.

---

# Reading Should Be Allowed

```cpp id="gbjlwm"
int a = d.day();
```

✔️ OK

---

```cpp id="jlwmq3"
int b = start_of_term.day();
```

Book asks:

```text id="0ttjlwm"
Why should this fail?
We are only reading.
```

---

ஆனால் compiler initially error தரும்.

ஏன்?

---

# Compiler Problem

Compiler doesn't know:

```cpp id="jlwm2d"
day()
```

modifies object or not.

---

Compiler thinks:

```text id="8qjlwm"
Maybe day() changes object internally
```

Just like:

```cpp id="jlwm4m"
add_day()
```

does.

---

# Solution — const Member Function

```cpp id="jlwmz8"
class Date
{
public:

    int day() const;
};
```

---

This:

```cpp id="jlwm3r"
const
```

AFTER argument list means:

```text id="m4jlwm"
This function promises
NOT to modify object
```

---

# Very Important

This:

```cpp id="jlwmn9"
const
```

is NOT:

```cpp id="7fjlwm"
return type const
```

---

It means:

```text id="6qjlwm"
current object is treated as const
```

---

# Book-Oriented Example

```cpp id="jlwm0v"
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar
};

struct Year
{
    int y;
};

class Date
{
public:

    Date(Year yy,
         Month mm,
         int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    int day() const
    {
        return d;
    }

    Month month() const
    {
        return m;
    }

    Year year() const
    {
        return y;
    }

    void add_day(int n)
    {
        d += n;
    }

private:

    Year y;
    Month m;
    int d;
};

int main()
{
    Date d
    {
        Year{2000},
        Month::jan,
        20
    };

    const Date cd
    {
        Year{2001},
        Month::feb,
        21
    };

    std::cout
        << d.day()
        << '\n';

    std::cout
        << cd.day()
        << '\n';

    d.add_day(1);

    std::cout
        << d.day()
        << '\n';
}
```

Output:

```text id="jlwm6p"
20
21
21
```

---

# Why cd.day() Works?

Because:

```cpp id="jlwm7n"
day() const
```

promises:

```text id="jlwm8b"
I will not modify object
```

---

Compiler says:

```text id="jlwm9x"
OK
safe for const object
```

---

# Why cd.add_day(1) Fails?

Suppose:

```cpp id="jlwm1a"
cd.add_day(1);
```

Compiler error.

Because:

```cpp id="jlwm2c"
add_day()
```

is NON-const member function.

---

Meaning:

```text id="jlwm3d"
This function may modify object
```

---

But:

```cpp id="jlwm4e"
cd
```

is const.

Cannot modify.

---

# Huge Design Principle

Stroustrup divides functions into:

---

# 1. Nonmodifying Operations

Only observe/read object.

Examples:

```cpp id="jlwm5g"
day()
month()
year()
size()
empty()
```

These should be:

```cpp id="jlwm6h"
const
```

---

# 2. Modifying Operations

Change object state.

Examples:

```cpp id="jlwm7i"
add_day()
push_back()
clear()
sort()
```

These should NOT be const.

---

# Compiler Protection

Book:

```cpp id="jlwm8j"
int Date::day() const
{
    ++d;

    return d;
}
```

Compiler error.

---

Why?

Because:

```cpp id="jlwm9k"
day()
```

promised:

```text id="jlwm0l"
I will not modify object
```

---

But:

```cpp id="jlwm1m"
++d
```

tries to modify.

Compiler catches violation.

---

# Important Mental Model

When compiler sees:

```cpp id="jlwm2n"
int day() const
```

it roughly treats object as:

```cpp id="jlwm3o"
const Date* this
```

inside function.

---

Meaning:

```text id="jlwm4p"
all members become read-only
```

inside that function.

# Full Professional Example

```cpp id="jlwm5bb"
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr
};

struct Year
{
    int y;
};

class Date
{
public:

    Date(Year yy,
         Month mm,
         int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    int day() const
    {
        return d;
    }

    Month month() const
    {
        return m;
    }

    Year year() const
    {
        return y;
    }

    void add_day(int n)
    {
        d += n;
    }

private:

    Year y;
    Month m;
    int d;
};

void print_date(const Date& dt)
{
    std::cout
        << dt.day()
        << '/'
        << static_cast<int>(dt.month())
        << '/'
        << dt.year().y
        << '\n';
}

int main()
{
    const Date today
    {
        Year{2025},
        Month::mar,
        10
    };

    print_date(today);
}
```

Output:

```text id="jlwm6cc"
10/3/2025
```

# Most Important Rule

If member function:

```text id="jlwm7dd"
does NOT change object
```

mark it:

```cpp id="jlwm8ee"
const
```

---

Examples:

```cpp id="jlwm9ff"
size() const
empty() const
year() const
day() const
name() const
balance() const
```

---

If function changes object:

DO NOT use const.

Examples:

```cpp id="jlwm0gg"
push_back()
add_day()
clear()
set_name()
withdraw()
```

---

# Final Big Idea of §8.7.4

`const` member functions give:

```text id="jlwm1hh"
Safety
Clarity
Compiler checking
Better interfaces
```

---

They tell both:

```text id="jlwm2ii"
Programmer
Compiler
```

that:

```text id="jlwm3jj"
"This function only observes object;
it does not modify it."
```

This is one of the most important habits in modern C++ programming.
