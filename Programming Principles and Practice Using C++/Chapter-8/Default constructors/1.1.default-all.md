> **"ஒரு object initializer இல்லாமல் உருவாக்கப்பட்டாலும் அது valid state-ல் இருக்க வேண்டும்."**

```text
default constructor
```

உள்ளது.

நம்முடைய Date class:

```cpp
class Date
{

    Date(Year y, Month m, int d);

```

---

இதில்:

```cpp
Date d;
```

எழுதினால்?

Compiler error.

ஏன்?

ஏனெனில்:

```text
Date-க்கு default constructor இல்லை
```

# Why Does C++ Force Initialization?

Because uninitialized objects are dangerous.

---

# Imagine Bad String

Suppose:

```cpp
string s;
```

was uninitialized.

Then:

```cpp
for(int i = 0; i < s.size(); ++i)
{
}
```

What is:

```cpp
s.size()
```

?

Random garbage.

---

Even worse:

```cpp
s[i]
```

might access random memory.

Crash.

---

# Same Problem with vector

```cpp
vector<string> v;

v.push_back("bad");
```

If vector uninitialized:

```text
where are elements stored?
how many elements exist?
```

Compiler/runtime doesn't know.

---

This breaks the object invariant.

---

# What Is Invariant?

Invariant means:

```text
Object must always remain valid
```

Example:

```text
string knows:
    size
    capacity
    memory location
```

---

Without constructor:

```text
object contains garbage
```

---

# Solution — Default Constructor

Book:

```cpp
class Date
{
public:

    Date()
        : y{Year{2001}},
          m{Month::jan},
          d{1}
    {
    }
};
```

---

This constructor takes:

```text
NO arguments
```

Hence:

```text
default constructor
```

---

# Now This Works

```cpp
Date d;
```

Compiler automatically calls:

```cpp
Date()
```

---

Memory becomes:

```text
d
├── y = 2001
├── m = jan
└── d = 1
```

# Book-Oriented Example

```cpp
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

struct Year
{
    int y;
};

class Date
{
public:

    Date()
        : y{Year{2001}},
          m{Month::jan},
          d{1}
    {
    }

    Date(Year yy, Month mm, int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    void print() const
    {
        std::cout
            << y.y
            << '/'
            << static_cast<int>(m)
            << '/'
            << d
            << '\n';
    }

private:

    Year y;
    Month m;
    int d;
};

int main()
{
    Date d;

    d.print();
}
```

Output:

```text
2001/1/1
```

# Important Idea

```cpp
Date d;
```

does NOT mean:

```text
leave memory uninitialized
```

---

It means:

```text
Call Date()
```

# Another Design — Default Member Initializers

Book improves design further.

Instead of:

```cpp
Date()
    : y{Year{2001}},
      m{Month::jan},
      d{1}
{
}
```

we can write:

```cpp
class Date
{
private:

    Year y{2001};
    Month m = Month::jan;
    int d = 1;
};
```

---

These are called:

```text
default member initializers
```

or:

```text
in-class initializers
```

---

# Why Better?

Every constructor automatically gets defaults.

Compiler automatically uses:

# Full Professional Example

```cpp
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

struct Year
{
    int y;
};

class Date
{
public:

    Date()
    {
    }

    Date(Year yy)
        : y{yy}
    {
    }

    Date(Year yy,
         Month mm,
         int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    void print() const
    {
        std::cout
            << y.y
            << '/'
            << static_cast<int>(m)
            << '/'
            << d
            << '\n';
    }

private:

    Year y{2001};

    Month m = Month::jan;

    int d = 1;
};

int main()
{
    Date d1;

    Date d2{Year{2025}};

    Date d3
    {
        Year{2025},
        Month::dec,
        24
    };

    d1.print();

    d2.print();

    d3.print();
}
```

Output:

```text
2001/1/1
2025/1/1
2025/12/24
```

# Final Big Ideas of §8.7.3

## 1

Every object should begin life valid.

---

## 2

Constructors establish invariants.

---

## 3

Default constructors allow:

```cpp
Date d;
string s;
vector<int> v;
```

to become safe.

---

## 4

Default member initializers reduce repetition.

---

## 5

Modern C++ prefers:

```cpp
T{}
```

because it guarantees initialization.

---

This chapter is one of the foundations of professional C++ design:

> **Never allow objects to exist in invalid or uninitialized states.**
