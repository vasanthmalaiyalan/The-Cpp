## நினைவில் வைக்க ஒரு Rule

`T{...}` பார்த்தால் compiler சுமார் இப்படி யோசிக்கும்:

```text
1. constructor இருக்கிறதா?
      yes -> constructor call

2. aggregate type ஆ?
      yes -> aggregate initialization

3. enum type ஆ?
      yes -> enum conversion

4. இல்லையெனில்
      normal list initialization rules
```

அதனால்:

```cpp

```

aggregate initialization அல்ல.

என்று செய்கிறது. `nov` என்று பெயரை lookup செய்து object உருவாக்குவதில்லை; `nov`-க்கும் இந்த object-க்கும் underlying value (`11`) ஒன்றே என்பதால் அவை சமமாக இருக்கும்.

-----------------

`ennum  உள்ளே member கிடையாது என்றால் enum உள்ளே இருக்கும் jan,feb இதெல்லாம் என்ன?`

அருமையான கேள்வி 👍

நீங்கள் இப்போது ஒரு முக்கியமான வேறுபாட்டை பிடித்துவிட்டீர்கள்.

நீங்கள் கேட்பது:

> enum-ல் member இல்லை என்றால் `jan`, `feb`, `mar` இவை என்ன?

---

## struct/class-ல் member என்றால்

```cpp
struct Point
{
    int x;
    int y;
};
```

இங்கே:

```cpp
x
y
```

**data members**

---

Object உருவாக்கும்போது:

```cpp
Point p{10,20};
```

Memory:

```text
p
 ├── x = 10
 └── y = 20
```

`x`, `y` object-க்குள் storage எடுக்கின்றன.

---

## enum-ல் jan/feb member அல்ல

```cpp
enum class Month
{
    jan = 1,
    feb = 2,
    mar = 3
};
```

இங்கே:

```cpp
jan
feb
mar
```

**enumerators** என்று அழைக்கப்படுகின்றன.

Member அல்ல.

---

Stroustrup சொல்வதும் அதுதான்:

> The body of an enumeration is simply a list of its enumerators.

---

## Enumerator என்றால்?

ஒரு named constant.

உதாரணம்:

```cpp
Month::jan
```

அதாவது:

```text
Month type-இன் ஒரு possible value
```

---

## Analogy

இதைப் போல நினையுங்கள்:

```cpp
enum class TrafficLight
{
    red,
    yellow,
    green
};
```

இங்கே:

```cpp
red
yellow
green
```

என்பவை fields அல்ல.

அவை:

```text
TrafficLight type-க்கு
அனுமதிக்கப்பட்ட values
```

---

## Difference

### Class

```cpp
class Person
{
    int age;
};
```

`age`:

```text
object-க்குள் storage இருக்கும்
```

---

### Enum

```cpp
enum class Month
{
    jan,
    feb,
    mar
};
```

`jan`:

```text
storage field அல்ல
ஒரு symbolic value
```

---

## Memory எப்படி இருக்கும்?

```cpp
Month m = Month::feb;
```

Memory roughly:

```text
m = 2
```

அவ்வளவுதான்.

---

Compiler:

```text
Month::feb
```

↓

```text
underlying value 2
```

என்று map பண்ணி வைத்திருக்கும்.

---

## அதனால் Month{11} ஏன் aggregate இல்லை?

Aggregate initialization-க்கு compiler-க்கு fields தேவை:

```cpp
Point{10,20}
```

↓

```text
10 -> x
20 -> y
```

---

ஆனால்:

```cpp
Month{11}
```

போது compiler கேட்கும்:

```text
11-ஐ எந்த field-க்கு assign பண்ண?
```

---

Field எதுவும் இல்லை.

ஏனெனில்:

```cpp
jan
feb
mar
```

members அல்ல.

Enumerators.

---

## இதை இப்படி நினைத்துக்கொள்ளுங்கள்

```cpp
enum class Month
{
    jan = 1,
    feb = 2,
    mar = 3
};
```

சுமார் compiler-ன் பார்வையில்:

```text
Month type

Allowed values:
    1 (jan)
    2 (feb)
    3 (mar)
```

---

அதனால்:

```cpp
Month m{2};
```

என்பது:

```text
2-ஐ Month type-ஆக convert செய்
```

---

அது:

```cpp
Month::feb
```

உடன் same representation கொண்ட value ஆக இருக்கும்.

---

### சுருக்கமாக

```cpp
enum class Month
{
    jan,
    feb,
    mar
};
```

இங்கே:

* `jan`, `feb`, `mar` → **enumerators**
* member variables அல்ல
* object-க்குள் storage எடுக்காது
* type-க்கு அனுமதிக்கப்பட்ட symbolic values
* அதனால் `Month{11}` aggregate initialization ஆகாது
* அது `int → Month` explicit enum conversion ஆகும்.

-----------------------------

``Month::feb`இப்படி கால் பண்ணும் போது offset பயன்படுத்தி தானே வேல்யூவை எடுக்கும்?`


இல்லை. `Month::feb`-ஐ access செய்யும்போது **class member போல object base address + offset** பயன்படுத்துவதில்லை.

இதுதான் முக்கிய வேறுபாடு:

---

## Class member access

```cpp
class Date
{
    int y;
    int m;
    int d;
};

Date obj;
```

`obj.m` access செய்யும்போது compiler சுமார்:

```text
address(obj) + offset_of(m)
```

என்று memory-லிருந்து value எடுக்கும்.

ஏனெனில் `m` என்பது object-க்குள் இருக்கும் data member.

---

## Enum enumerator access

```cpp
enum class Month
{
    jan = 1,
    feb = 2,
    mar = 3
};
```

இங்கே:

```cpp
Month::feb
```

என்பது object member அல்ல.

இது ஒரு **named constant**.

Compiler compile time-லேயே தெரிந்து வைத்திருக்கும்:

```text
Month::jan = 1
Month::feb = 2
Month::mar = 3
```

அதனால்:

```cpp
Month m = Month::feb;
```

சுமார்:

```cpp
Month m = static_cast<Month>(2);
```

போல machine code உருவாகும்.

Memory-லிருந்து offset கணக்கிட்டு தேடுவதில்லை.

---

## Example

```cpp
if (m == Month::feb)
{
}
```

Compiler உள்ளே சுமார்:

```cpp
if (m == static_cast<Month>(2))
{
}
```

என்று மாற்றலாம்.

---

## Why?

ஏனெனில் enumerators (`jan`, `feb`, `mar`) என்பது:

* data members அல்ல
* object fields அல்ல
* compile-time constants

---

## Mental model

Class:

```text
Date object
 ├── y
 ├── m
 └── d
```

`obj.m`

↓

```text
object address + offset
```

---

Enum:

```text
Month
 ├── jan = 1
 ├── feb = 2
 └── mar = 3
```

`Month::feb`

↓

```text
compile-time constant value 2
```

↓

offset lookup இல்லை.

அதனால் `Month::feb` என்பது memory-லிருந்து field-ஐ வாசிப்பது அல்ல; compiler ஏற்கனவே அறிந்திருக்கும் enum constant-ஐ பயன்படுத்துவது.
