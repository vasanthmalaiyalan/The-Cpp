இந்த **§8.4.2 Member functions and constructors**-ல் Stroustrup ஒரு பெரிய பிரச்சனையை காட்டுகிறார்:

> `struct + helper functions` மட்டும் போதாது.
> Programmers helper functions-ஐ மறந்து விடலாம்.

அதனால் C++ **constructor** மற்றும் **member function**-களை வழங்குகிறது.

---

# Problem with Previous Design

நாம் முன்பு:

```cpp
struct Date
{
    int y;
    int m;
    int d;
};

void init_day(Date& dd, int y, int m, int d);
void add_day(Date& dd, int n);
```

என்று எழுதியிருந்தோம்.

---

Usage:

```cpp
Date today;

init_day(today, 2025, 12, 24);
```

---

## What can go wrong?

Someone forgets:

```cpp
Date today;

std::cout << today.d;
```

❌ Undefined value.

Because:

```cpp
today.y
today.m
today.d
```

never initialized.

---

# Book's Bad Example

```cpp
void f()
{
    Date today;

    std::cout << today.d << '\n';

    init_day(today, 2025, 12, 24);
}
```

Problem:

```text
today used before initialization
```

This bug looks innocent.

---

# Another Problem

Someone manually adds a day:

```cpp
Date tomorrow;

tomorrow.y = today.y;
tomorrow.m = today.m;
tomorrow.d = today.d + 1;
```

Looks correct.

---

But suppose:

```cpp
today = 31/12/2025
```

Then:

```cpp
tomorrow.d = 32
```

Invalid date.

---

This is Stroustrup's point:

```text
Bad code often looks normal.
```

---

# Solution: Put Operations Inside Date

Instead of:

```cpp
add_day(today, 1);
```

make it:

```cpp
today.add_day(1);
```

Now operation belongs to Date.

---

# First Real Date Design

```cpp
struct Date
{
    int y;
    int m;
    int d;

    Date(int year, int month, int day);

    void add_day(int n);
};
```

Notice:

```cpp
Date(...)
```

and

```cpp
add_day(...)
```

inside struct.

These are called:

```text
member functions
```

---

# Constructor

Special member function:

```cpp
Date(int year, int month, int day);
```

Name equals class name.

---

This is NOT:

```cpp
void Date(...)
```

No return type.

---

Purpose:

```text
initialize object
```

---

# Complete Book-Oriented Example

```cpp
#include <iostream>
#include <stdexcept>

struct Date
{
    int y;
    int m;
    int d;

    Date(int year, int month, int day);

    void add_day(int n);
};

Date::Date(int year, int month, int day)
{
    if(month < 1 || month > 12)
    {
        throw std::runtime_error("invalid month");
    }

    if(day < 1 || day > 31)
    {
        throw std::runtime_error("invalid day");
    }

    y = year;
    m = month;
    d = day;
}

void Date::add_day(int n)
{
    d += n;
}

int main()
{
    Date last{2025,12,31};

    last.add_day(1);

    std::cout
        << last.d << '/'
        << last.m << '/'
        << last.y
        << '\n';
}
```

---

# Why Constructor Is Better

Old way:

```cpp
Date today;

init_day(today,2025,12,24);
```

Maybe forgotten.

---

New way:

```cpp
Date today{2025,12,24};
```

Initialization mandatory.

---

# Compiler Protection

Book example:

```cpp
Date birthday;
```

Compiler error.

Why?

Because:

```cpp
Date(int,int,int)
```

requires arguments.

---

Compiler says:

```text
I need year month day
```

---

This prevents:

```cpp
Date today;
```

with uninitialized values.

---

# Initialization Styles

### Preferred Modern Style

```cpp
Date last{2025,12,31};
```

---

### Also Valid

```cpp
Date next = {2025,12,31};
```

---

### Verbose Style

```cpp
Date next = Date{2025,12,31};
```

---

All create same object.

---

# Why `{}`?

Stroustrup strongly prefers:

```cpp
Date d{2025,12,31};
```

instead of:

```cpp
Date d(2025,12,31);
```

because braces work uniformly everywhere.

---

Even built-in types:

```cpp
int x{7};
```

---

instead of:

```cpp
int x = 7;
```

---

# Member Function Call

Book:

```cpp
last.add_day(1);
```

Meaning:

```text
call add_day() for object last
```

---

Notice:

```cpp
add_day(1);
```

alone is invalid.

Compiler asks:

```text
Which Date object?
```

Because member functions belong to objects.

---

Need:

```cpp
last.add_day(1);
today.add_day(1);
birthday.add_day(1);
```

---

# Internal Mental Model

When compiler sees:

```cpp
last.add_day(1);
```

Think roughly:

```cpp
add_day(&last,1);
```

The object (`last`) is automatically passed.

---

# Most Important Lesson of §8.4.2

Stroustrup is moving from:

```cpp
struct Date
{
    int y;
    int m;
    int d;
};
```

plus external helper functions

↓

to

```cpp
struct Date
{
    int y;
    int m;
    int d;

    Date(...);
    void add_day(...);
};
```

where:

* construction is mandatory
* validation happens automatically
* operations belong to the type
* forgetting initialization becomes impossible

This is the first step from a **simple data structure** toward a **real class abstraction**.
