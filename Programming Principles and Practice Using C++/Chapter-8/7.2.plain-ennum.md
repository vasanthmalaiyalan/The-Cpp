இந்த **§8.5.1 "Plain" enumerations**-ல் Stroustrup சொல்லும் முக்கிய கருத்து:

> **"Old-style enum வேலை செய்யும். ஆனால் modern C++-ல் `enum class` safer."**

---

# Two Types of Enumerations

C++-ல்:

## Modern (Recommended)

```cpp
enum class Month
{
    jan = 1,
    feb,
    mar
};
```

---

## Old Style (Plain Enum)

```cpp
enum Month
{
    jan = 1,
    feb,
    mar
};
```

---

இரண்டுமே enumeration.

ஆனால் behavior வேறு.

---

# Book Example

```cpp
enum Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};
```

---

# Difference #1 — Scope Pollution

## enum class

```cpp
enum class Month
{
    jan = 1,
    feb
};

Month m = Month::feb;
```

Must write:

```cpp
Month::feb
```

---

This fails:

```cpp
Month m = feb;
```

Compiler error.

---

Why?

Because:

```text
feb is inside Month scope
```

---

# Plain Enum

```cpp
enum Month
{
    jan = 1,
    feb
};

Month m = feb;
```

Works.

---

Because:

```text
jan
feb
```

are automatically exported into surrounding scope.

---

Compiler behaves as if:

```text
jan available everywhere
feb available everywhere
```

---

# Why Is This Dangerous?

Suppose:

```cpp
enum Month
{
    jan,
    feb,
    mar,
    dec
};
```

---

And:

```cpp
#include <iostream>
```

contains:

```cpp
std::dec
```

(decimal formatter)

---

Now:

```cpp
dec
```

has two meanings.

Conflict.

---

This is what Stroustrup means by:

```text
scope pollution
```

---

# Example

```cpp
#include <iostream>

enum Month
{
    jan = 1,
    feb,
    mar,
    dec
};

int main()
{
    std::cout << dec << '\n';
}
```

Compiler may become confused because:

```text
Month::dec
std::dec
```

both exist.

---

# enum class Prevents This

```cpp
enum class Month
{
    jan = 1,
    feb,
    mar,
    dec
};
```

Now:

```cpp
Month::dec
```

and

```cpp
std::dec
```

are separate.

No collision.

---

# Difference #2 — Automatic Conversion to int

Plain enum allows:

```cpp
enum Month
{
    jan = 1,
    feb = 2
};

Month m = feb;

int x = m;
```

Works.

---

Compiler automatically converts:

```text
feb
↓
2
```

---

Output:

```cpp
#include <iostream>

enum Month
{
    jan = 1,
    feb = 2
};

int main()
{
    Month m = feb;

    int x = m;

    std::cout << x << '\n';
}
```

Output:

```text
2
```

---

# enum class Does NOT Allow This

```cpp
enum class Month
{
    jan = 1,
    feb = 2
};

Month m = Month::feb;

int x = m;
```

Compiler error.

---

Need explicit conversion:

```cpp
int x = static_cast<int>(m);
```

or:

```cpp
int x = to_int(m);
```

---

# Why Is Automatic Conversion Dangerous?

Because compiler starts treating Month as int.

---

Book Example

```cpp
void bad_code(Month m)
{
    if (m == 17)
    {
        do_something();
    }
}
```

---

Question:

```text
17th month exists?
```

No.

---

But plain enum converts:

```text
Month
↓
int
```

comparison becomes legal.

---

Compiler accepts nonsense.

---

# Another Dangerous Example

Suppose:

```cpp
enum Month
{
    jan = 1,
    feb = 2
};

enum Day
{
    monday = 1,
    tuesday = 2
};
```

---

Then:

```cpp
if (m == monday)
{
}
```

Compiles.

---

Because:

```text
Month → int
Day   → int
```

---

Compiler compares:

```text
1 == 1
```

instead of:

```text
Month == Day
```

---

This is logically wrong.

---

# Book-Oriented Demonstration

## Bad (Plain Enum)

```cpp
#include <iostream>

enum Month
{
    jan = 1,
    feb = 2
};

enum Day
{
    monday = 1,
    tuesday = 2
};

int main()
{
    Month m = jan;

    if(m == monday)
    {
        std::cout << "Compiler allowed nonsense\n";
    }
}
```

Output:

```text
Compiler allowed nonsense
```

---

# Good (enum class)

```cpp
#include <iostream>

enum class Month
{
    jan = 1,
    feb = 2
};

enum class Day
{
    monday = 1,
    tuesday = 2
};

int main()
{
    Month m = Month::jan;

    if(m == Day::monday)
    {
    }
}
```

Compiler error.

---

Compiler says:

```text
Month and Day are different types
```

Exactly what we want.

---

# Complete Modern Example

```cpp
#include <iostream>

enum class Month
{
    jan = 1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

int to_int(Month m)
{
    return static_cast<int>(m);
}

int main()
{
    Month current = Month::aug;

    std::cout
        << to_int(current)
        << '\n';
}
```

Output:

```text
8
```

# What Stroustrup Wants You To Learn

Old C++:

```cpp
enum Month
{
    jan,
    feb
};
```

Problems:

```text
Names leak into scope
Implicit int conversions
Easy to write bugs
```

---

Modern C++:

```cpp
enum class Month
{
    jan,
    feb
};
```

Benefits:

```text
Strong typing
No scope pollution
Safer comparisons
Explicit conversions
Cleaner code
```

---

### Stroustrup's Recommendation

Use:

```cpp
enum class
```

for almost all new code.

Only expect:

```cpp
enum
```

(plain enums) in older C/C++ codebases.
