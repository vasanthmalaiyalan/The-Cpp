ஆமாம்! இதுதான் pointer arithmetic-ன் முக்கியமான point. 🔥

நீ கேட்டது:

```cpp
FieldInfo* end = begin + fields.size();
```

இங்கே `sizeof(FieldInfo)=56` என்றால் என்ன நடக்கும்?

---

Suppose:

```cpp
FieldInfo* begin = 0x5000;
```

and

```cpp
fields.size() = 3;
```

---

நீங்க நினைப்பது போல:

```cpp
0x5000 + 3
```

ஆகாது.

ஏனெனில் `begin` type:

```cpp
FieldInfo*
```

---

Compiler rule:

```cpp
ptr + n
```

=

```cpp
(char*)ptr + (n * sizeof(T))
```

where:

```cpp
T = FieldInfo
```

---

அதனால்:

```cpp
begin + fields.size()
```

↓

```cpp
begin + 3
```

↓

```cpp
(char*)0x5000 + (3 * 56)
```

↓

```cpp
(char*)0x5000 + 168
```

---

168 decimal:

```text
168 = 0xA8
```

---

Result:

```text
0x5000 + 0xA8
=
0x50A8
```

---

அதனால்:

```cpp
FieldInfo* end = begin + fields.size();
```

becomes:

```text
end = 0x50A8
```

---

இதைக் compiler conceptually இப்படி பார்க்கலாம்:

```cpp
FieldInfo* begin = 0x5000;

FieldInfo* end =
    reinterpret_cast<FieldInfo*>(
        reinterpret_cast<char*>(begin)
        +
        fields.size() * sizeof(FieldInfo)
    );
```

---

Visual:

```text
sizeof(FieldInfo)=56

Address

0x5000  age
0x5038  salary
0x5070  grade
0x50A8  end
```

---

அதனால்:

```cpp
++begin;
```

என்றாலும்:

```cpp
begin = begin + 1;
```

↓

```cpp
(char*)begin + 56
```

---

மற்றும்:

```cpp
begin + 3
```

↓

```cpp
(char*)begin + (3 * 56)
```

---

அதனால் STL iterator traversal-ன் அடிப்படை rule:

```cpp
T* ptr;
```

என்றால்

```cpp
ptr + 1
```

என்பது:

```cpp
address + sizeof(T)
```

ஆகும்.

`1 byte` அல்ல. `sizeof(T)` bytes jump ஆகும்.

அதனால்தான்:

```cpp
FieldInfo* end = begin + fields.size();
```

இங்கே `56` ஒரு முறை மட்டும் அல்ல,

```text
56 × 3 = 168 bytes
```

jump செய்து `0x50A8` கிடைக்கிறது. 🚀

## முக்கியமான விஷயம்

இந்த object:

```cpp
{
    "age",
    sizeof(int),
    alignof(int),
    0
}
```

உள்ளே `"age"` string இருப்பதால் பலர்:

> object size 3 bytes தானே?

என்று நினைப்பார்கள்.

ஆனால் இல்லை.

`std::string` தானே ஒரு object.

பொதுவாக:

```cpp
sizeof(std::string)
```

சுமார்:

```text
24 அல்லது 32 bytes
```

---

அதனால்:

```cpp
sizeof(FieldInfo)
```

என்பது:

```text
string object size
+
size_t
+
size_t
+
size_t
```

ஆக கணக்கிடப்படும்.

---

நீங்கள் உங்கள் machine-ல் exact size பார்க்க:

```cpp
#include <iostream>
#include <string>

struct FieldInfo
{
    std::string name;
    size_t size;
    size_t alignment;
    size_t offset;
};

int main()
{
    std::cout
        << sizeof(std::string)
        << '\n';

    std::cout
        << sizeof(FieldInfo)
        << '\n';
}
```

Run செய்தால் உங்கள் compiler/STL implementation-க்கு exact value தெரியும்.

அதனால் **ஆம்**, `push_back({...})`-ல் உருவாகும் அந்த ஒரு `FieldInfo` temporary object itself சுமார் **56 bytes** இருக்கலாம்; vector heap-ல் store செய்வதும் அதே size கொண்ட object-ஐத்தான்.


-------------------

`நாம vector concept பார்க்கும்போது vector உள்ளே heap address உருவாக்குவது malloc என்று பார்த்தோம் ஆனால் stack உள்ளேயும் basic int,double எல்லாம் ஸ்டோர் ஆகும் தானே அந்த அட்ரஸை உருவாக்குவது எது?`

அருமையான கேள்வி. 🔥

நீங்கள் இப்போது:

> Heap memory-க்கு `malloc/new` address உருவாக்குகிறது என்று புரிந்தது.
>
> ஆனால்
>
> ```cpp
> int x = 10;
> double y = 20;
> ```
>
> போன்ற stack variables-க்கு address யார் உருவாக்குகிறார்கள்?

என்று கேட்கிறீர்கள்.

---

# Short Answer

**Stack address-ஐ `malloc()` உருவாக்குவதில்லை.**

அதை:

```text
Operating System
+
CPU Stack Pointer Register
+
Compiler generated code
```

மூன்றும் சேர்ந்து உருவாக்குகின்றன.

---

## Example

```cpp
int main()
{
    int x = 10;
    int y = 20;
}
```

Compiler parse செய்ததும்:

```text
x size = 4
y size = 4
```

---

Compiler கணக்கிடுகிறது:

```text
Need stack space = 8 bytes
```

---

Conceptually compiler generated code:

```asm
sub rsp, 8
```

(64-bit example)

---

இதன் அர்த்தம்:

```text
Stack Pointer
↓
8 bytes கீழே நகர்த்து
```

---

Before:

```text
rsp = 0x1000
```

After:

```text
rsp = 0x0FF8
```

---

இப்போது:

```text
0x0FF8 -> x
0x0FFC -> y
```

---

Address-ஐ யார் கொடுத்தார்கள்?

**CPU stack pointer register (`rsp`)**

இதனால்:

**Heap address-ஐ allocator (`malloc/new`) கொடுக்கிறது.**

**Stack address-ஐ compiler generated stack-frame layout + CPU stack pointer (`rsp/esp`) கொடுக்கிறது.** இதுதான் இரண்டுக்கும் உள்ள அடிப்படை வித்தியாசம். 🚀
