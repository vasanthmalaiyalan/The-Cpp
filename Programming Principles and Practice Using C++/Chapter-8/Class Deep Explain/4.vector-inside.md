## முதலில் `FieldInfo`

```cpp
struct FieldInfo
{
    std::string name;
    size_t size;
    size_t alignment;
    size_t offset;
};
```

Compiler parse செய்த பிறகு metadata:

```text
FieldInfo

field #0 -> name
field #1 -> size
field #2 -> alignment
field #3 -> offset
```

இந்த order முக்கியம்.

அதனால் உன் சந்தேகத்துக்கான நேரடி பதில்:

✅ Compiler `push_back()`-ன் parameter type (`FieldInfo`) பார்த்து,

✅ `FieldInfo`-ன் member order (`name,size,alignment,offset`) metadata-ஐ பயன்படுத்தி,

✅ initializer list values-ஐ அந்த fields-க்கு map செய்கிறது.

❌ `offset` value-ஐ பார்த்து map செய்யாது.

❌ return type காரணமாக அல்ல.

**Type definition (`FieldInfo`) + field order** தான் mapping-க்கு அடிப்படை.


-------------------------

``அதனால் உன் சந்தேகத்துக்கான நேரடி பதில்:
✅ Compiler push_back()-ன் parameter type (FieldInfo) பார்த்து,
✅ FieldInfo-ன் member order (name,size,alignment,offset) metadata-ஐ பயன்படுத்தி,

ஆம்! இப்போது நீ compiler மற்றும் vector internals-ன் சரியான தொடர்பை பிடித்துவிட்டாய். 🔥

ஆனால் ஒரு சிறிய correction:

நீ சொன்னது:

> vector உள்ளே heap memory create ஆவதற்கு `FieldInfo` type size தேவை, அதனால் total size calculate செய்து `FieldInfo temp`-ஐ vector உள்ளே சேமிக்கிறது

**பெரும்பாலும் சரி.** ஆனால் sequence கொஞ்சம் வேறாக நடக்கும்.

அதனால் உன் sentence-ஐ compiler language-ல் சரியாக எழுதினால்:

```text

↓

Compiler already knows sizeof(FieldInfo)

↓

Vector allocates sizeof(FieldInfo) * capacity bytes

↓

Initializer list becomes temporary FieldInfo object

↓

That FieldInfo object is copied/moved into the vector's heap storage
```

இதுதான் actual flow. `offset` field என்பது வெறும் `FieldInfo` object-ன் data மட்டுமே; ஆனால் `sizeof(FieldInfo)` என்பது compiler உருவாக்கிய type layout metadata-லிருந்து வருகிறது. இந்த இரண்டையும் பிரித்துப் பார்த்தால் compiler internals மிகவும் தெளிவாக புரியும்.
