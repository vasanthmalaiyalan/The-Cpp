இந்த **§8.7 Class interfaces**-ல் Stroustrup சொல்லும் மிக முக்கியமான விஷயம்:

> **"Class எழுதுவது மட்டும் போதாது. நல்ல interface உடன் class வடிவமைக்க வேண்டும்."**

அதாவது:

```text
எப்படி users class-ஐ பயன்படுத்துவார்கள்?
```

என்பதே முக்கியம்.

---

# What is Interface?

```cpp
class Date
{
public:
    Date(int y,int m,int d);

    void add_day(int n);

    int month();

private:
    int y;
    int m;
    int d;
};
```

இதில்:

```cpp
public:
```

பகுதி:

```text
interface
```

---

User பார்க்கும் பகுதி:

```cpp
Date(...)
add_day(...)
month()
```

---

இதில்:

```cpp
private:
```

பகுதி:

```text
implementation details
```

User directly use செய்ய முடியாது.

---

# Stroustrup's Design Principles

Book 6 முக்கிய principles சொல்கிறது.

ஒன்றொன்றாகப் பார்ப்போம்.

---

# 1. Keep interfaces complete

Meaning:

```text
User-க்கு தேவையான operations எல்லாம் இருக்க வேண்டும்
```

---

## Bad Example

```cpp
class Date
{
public:
    Date(int y,int m,int d);

private:
    int y;
    int m;
    int d;
};
```

---

Problem:

```cpp
Date d{2025,12,24};
```

பிறகு:

```text
month எப்படி படிப்பது?
day எப்படி?
print எப்படி?
```

Interface incomplete.

---

# Better Version

```cpp
#include <iostream>

class Date
{
public:

    Date(int yy,int mm,int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    int year()
    {
        return y;
    }

    int month()
    {
        return m;
    }

    int day()
    {
        return d;
    }

private:

    int y;
    int m;
    int d;
};

int main()
{
    Date d{2025,12,24};

    std::cout
        << d.day() << '/'
        << d.month() << '/'
        << d.year()
        << '\n';
}
```

Now interface useful.

---

# 2. Keep interfaces minimal

Meaning:

```text
தேவையில்லாத functions சேர்க்காதே
```

---

## Bad Design

```cpp
class Date
{
public:

    void print_date();
    void show_date();
    void display_date();
    void output_date();
    void reveal_date();
};
```

All same thing.

Messy interface.

---

# Good Design

```cpp
class Date
{
public:

    void print();
};
```

Simple.

Minimal.

---

# Book Principle

```text
Keep interface as small as possible,
but no smaller
```

---

# 3. Provide constructors

Without constructor:

```cpp
struct Date
{
    int y;
    int m;
    int d;
};

Date d;
```

Danger:

```text
uninitialized object
```

---

# Good Design

```cpp
class Date
{
public:

    Date(int yy,int mm,int dd);

private:

    int y;
    int m;
    int d;
};
```

Now:

```cpp
Date d;
```

Compile error.

Must initialize.

---

# Best Constructor Example

```cpp
#include <iostream>
#include <stdexcept>

class Date
{
public:

    Date(int yy,int mm,int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
        if(mm < 1 || mm > 12)
        {
            throw std::runtime_error("invalid month");
        }
    }

private:

    int y;
    int m;
    int d;
};

int main()
{
    Date d{2025,12,24};
}
```

# 4. Support copying (or prohibit it)

Book says:

```text
Objects usually should copy correctly
```

---

Example:

```cpp
Date d1{2025,12,24};

Date d2 = d1;
```

Now:

```text
d2 should become exact copy
```

---

# Example

```cpp
#include <iostream>

class Date
{
public:

    Date(int yy,int mm,int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    void print()
    {
        std::cout
            << d << '/'
            << m << '/'
            << y
            << '\n';
    }

private:

    int y;
    int m;
    int d;
};

int main()
{
    Date d1{2025,12,24};

    Date d2 = d1;

    d2.print();
}
```

Output:

```text
24/12/2025
```

# 5. Use types for argument checking

Very important.

---

## Bad

```cpp
void set_month(int x);
```

User can do:

```cpp
set_month(999);
```

---

# Better

```cpp
enum class Month
{
    jan=1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

void set_month(Month m);
```

Now:

```cpp
set_month(999);
```

Compile error.

---

# Complete Example

```cpp
#include <iostream>

enum class Month
{
    jan=1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

class Date
{
public:

    Date(int yy,Month mm,int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
    }

    void print()
    {
        std::cout
            << d << '/'
            << static_cast<int>(m)
            << '/'
            << y
            << '\n';
    }

private:

    int y;
    Month m;
    int d;
};

int main()
{
    Date d{2025,Month::dec,24};

    d.print();
}
```

# 6. Identify nonmodifying member functions

Meaning:

```text
இந்த function object-ஐ மாற்றாது
```

என்பதை compiler-க்கு சொல்ல வேண்டும்.

---

# Example

```cpp
int month() const
{
    return m;
}
```

---

Meaning:

```text
month() object state-ஐ modify செய்யாது
```

---

# Why Important?

Compiler catches mistakes.

---

Example

```cpp
class Date
{
public:

    int month() const
    {
        return m;
    }

private:

    int m;
};
```

---

Inside:

```cpp
m = 99;
```

எழுதினால் compiler error.

---

# Full Professional Example

```cpp
#include <iostream>
#include <stdexcept>

enum class Month
{
    jan=1,
    feb,
    mar,
    apr,
    may,
    jun,
    jul,
    aug,
    sep,
    oct,
    nov,
    dec
};

class Date
{
public:

    Date(int yy,Month mm,int dd)
        : y{yy},
          m{mm},
          d{dd}
    {
        if(dd < 1 || dd > 31)
        {
            throw std::runtime_error("invalid day");
        }
    }

    int year() const
    {
        return y;
    }

    Month month() const
    {
        return m;
    }

    int day() const
    {
        return d;
    }

    void add_day(int n)
    {
        d += n;
    }

private:

    int y;
    Month m;
    int d;
};

std::ostream&
operator<<(std::ostream& os,
           const Date& dt)
{
    return os
        << dt.day()
        << '/'
        << static_cast<int>(dt.month())
        << '/'
        << dt.year();
}

int main()
{
    Date today{2025,Month::dec,24};

    std::cout
        << today
        << '\n';

    today.add_day(1);

    std::cout
        << today
        << '\n';
}
```

Output:

```text
24/12/2025
25/12/2025
```

# What Stroustrup Wants You To Learn

A good class interface should:

```text
Complete
Minimal
Safe
Easy to use
Hard to misuse
```

Good interface:

```cpp
Date today{2025,Month::dec,24};

today.add_day(1);

cout << today;
```

Natural and safe.

---

Bad interface forces users to write:

```cpp
today.y = ...
today.m = ...
today.d = ...
```

which creates bugs.

---

### Final Big Idea

Professional C++ is not just:

```text
writing classes
```

It is:

```text
designing clean interfaces
that make correct usage easy
and incorrect usage difficult
```

இதுதான் §8 முழு chapter-ன் core philosophy.
