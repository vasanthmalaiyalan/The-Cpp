இந்த **§8.3 Interface and Implementation**-ன் முக்கிய idea:

> **"User-க்கு தேவையானதை மட்டும் காட்டுங்கள்; உள்ளே எப்படி வேலை செய்கிறது என்பதை மறைத்து வையுங்கள்."**

இதுதான் **Encapsulation** என்ற OOP principle.

---

# Example 1: Private member access error

```cpp
#include <iostream>

class X
{
private:
    int m;   // private member

public:
    void set_m(int value)
    {
        m = value;
    }

    int get_m()
    {
        return m;
    }
};

int main()
{
    X x;

    x.set_m(10);

    std::cout << x.get_m() << '\n';

    // x.m = 20;   // ERROR: m is private

    return 0;
}
```

### Output

```text
10
```

---

# Why private?

Suppose bank account:

❌ Bad design

```cpp
class BankAccount
{
public:
    int balance;
};
```

Then anyone can do:

```cpp
account.balance = -1000000;
```

Invalid state!

---

# Better design using interface

```cpp
#include <iostream>

class BankAccount
{
private:
    int balance;

public:
    void deposit(int amount)
    {
        if (amount > 0)
            balance += amount;
    }

    int get_balance()
    {
        return balance;
    }

    BankAccount()
    {
        balance = 0;
    }
};

int main()
{
    BankAccount acc;

    acc.deposit(1000);

    std::cout << "Balance = "
              << acc.get_balance()
              << '\n';
}
```

Output:

```text
Balance = 1000
```

# Example matching the book

Book:

```cpp
class X {
    int m;
    int mf(int);

public:
    int f(int i)
    {
        m = i;
        return mf(i);
    }
};
```

Full compilable version:

```cpp
#include <iostream>

class X
{
private:
    int m;

    int mf(int value)
    {
        return value * 2;
    }

public:
    int f(int i)
    {
        m = i;
        return mf(i);
    }
};

int main()
{
    X x;

    int y = x.f(2);

    std::cout << y << '\n';
}
```

Output:

```text
4
```

# What happens internally?

```cpp
X x;
```

Object created.

---

```cpp
x.f(2);
```

Allowed because `f()` is public.

---

Inside `f()`:

```cpp
m = i;
```

Private member accessed.

Allowed because class member functions can access private members.

---

Then:

```cpp
return mf(i);
```

Private function called.

Again allowed because we're inside the same class.

# struct vs class

### struct

```cpp
struct Point
{
    int x;
    int y;
};
```

Usage:

```cpp
Point p;

p.x = 10;
p.y = 20;
```

Everything public by default.

---

Equivalent class:

```cpp
class Point
{
public:
    int x;
    int y;
};
```

Exactly same behavior.

---

# When to use struct?

Simple data containers:

```cpp
struct Point
{
    int x;
    int y;
};

struct Color
{
    int r;
    int g;
    int b;
};
```

No rules to enforce.

---

# When to use class?

When data must be protected or validated:

```cpp
class Date
{
private:
    int day;
    int month;
    int year;

public:
    void set_day(int d);
    void set_month(int m);
};
```

You don't want:

```cpp
date.day = 100;
```

because that's not a valid date.

# Real-world analogy

Think of a car:

### Interface (public)

```text
start()
stop()
accelerate()
brake()
```

User can use these.

---

### Implementation (private)

```text
fuel injection
engine timing
sensor logic
gear calculations
```

Driver doesn't touch these directly.

---

That's exactly what:

```cpp
public:
```

and

```cpp
private:
```

are designed to represent in C++.

### Summary

```text
public   = interface (what users can access)

private  = implementation (internal details)

class    = private by default

struct   = public by default

Good OOP:
Hide data
Expose operations
Protect invariants
```

This separation of **interface vs implementation** is one of the most important ideas in professional C++ design.
